This flow is the right pattern for efficiency and stability:

- QuerySynaptAgent calls Synapt once and produces the handoff
- NetworkPredictionAgent runs independently with current metrics
- RCAAgent consumes:
  - rca_handoff
  - current_metrics / network_prediction
- RCAAgent does not call Synapt again
- It only reads the prior advisory Synapt answer already stored in rca_handoff["synapt_context"]

That means:
- no re-trigger loop
- no extra agent connection
- no efficiency drop from repeated Synapt calls
- no break in the decision chain because the output is passed as structured data, not a new agent invocation
